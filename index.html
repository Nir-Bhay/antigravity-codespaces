Connect, switch accounts, fix SSH and keep agent sessions alive without leaving Cursor, Antigravity, VS Code, Windsurf or VSCodium.

The problem

Your editor is local. Your workspaces aren't.

Running GitHub Codespaces from an AI-first editor usually means hand-written SSH config, account juggling and connections that drop in the middle of an agent's task.

01

Account switching

Personal, work and client codespaces live under different GitHub accounts.

02

SSH setup

Host entries, platform settings and host keys all have to be right before anything connects.

03

Opaque failures

Errors like exit 127 or 255 rarely say that the real cause was gh auth.

04

Dropped sessions

Long-running AI agent work dies when an idle tunnel times out.

How it works

Your editor, your GitHub account, a direct path.

The extension drives the official GitHub CLI and your IDE's Remote-SSH extension. Credentials stay in gh and the IDE's SecretStorage.

Your IDE

Cursor, Antigravity, VS Code, Windsurf or VSCodium with the extension and Remote-SSH.

GitHub CLI

gh codespace ssh under the account you picked. Preflight catches auth and scope problems first.

Your codespace

A Linux container on GitHub, billed to your own account or organization.

Setup

Set it up in your IDE.

Same steps everywhere: install the gh CLI, sign in, add the extension and a Remote-SSH extension, then connect.

  1. Install the GitHub CLI from cli.github.com and run gh auth login -s codespace.
  2. Open the Extensions view; Antigravity uses Open VSX, then search Antigravity Codespaces Pro.
  3. Remote-SSH: Antigravity's remote support, or jeanp413.open-remote-ssh.
  4. Run Codespaces: Setup Doctor to check everything.
  5. Press Alt+C and pick a codespace.
  6. Full walkthrough: full Google Antigravity setup guide.

Usage, from the source

Know exactly how much quota is left.

The extension reads GitHub's billing API for the active gh account, which needs the user scope. Compute and storage are separate quotas and are never added together.

PlanCompute / monthStorage / month
GitHub Free120 core-hours15 GB-month
GitHub Pro180 core-hours20 GB-month
OrganizationsNo free quota, billed to the org

Source: GitHub Docs, About billing for Codespaces.

For AI agents

Let your IDE's agent set it up.

Paste this into the agent in Cursor, Antigravity, Windsurf or Codex. It installs and configures the extension and stops to ask before signing you in.

agent prompt
Set up the "Antigravity Codespaces Pro" extension (ID: nirbhay-hiwse.antigravity-codespaces) in this IDE so I can connect to my GitHub Codespaces over SSH.

Follow https://github.com/Nir-Bhay/antigravity-codespaces/blob/main/AGENT_SETUP.md step by step:
1. Detect which IDE and operating system this is.
2. Check that the GitHub CLI (gh) and an OpenSSH client are installed. Install whatever is missing.
3. Install the extension from Open VSX, or from the latest .vsix release if this IDE cannot reach Open VSX.
4. Install the Remote-SSH extension the guide lists for this IDE. In Windsurf, use the built-in SSH and install nothing.
5. Ask me before running "gh auth login -s codespace", and let me finish the browser sign-in myself.
6. Run "Codespaces: Setup Doctor", fix what it reports, and tell me exactly what you changed.
Do not delete any codespace and do not edit anything in ~/.ssh/config outside the blocks this extension manages.

FAQ

Questions developers ask.

How do I connect Cursor to GitHub Codespaces?

Install the GitHub CLI and run gh auth login -s codespace. Install Antigravity Codespaces Pro from Open VSX in Cursor; Cursor's bundled anysphere.remote-ssh is used automatically. Run Codespaces: Setup Doctor, then press Alt+C and pick a codespace.

Does it work in Google Antigravity?

Yes. Antigravity installs extensions from Open VSX. Search for Antigravity Codespaces Pro, install it, and connect through Antigravity's remote support or the Open Remote - SSH extension.

Why does the official GitHub Codespaces extension not work in Cursor or Antigravity?

These editors install extensions from Open VSX, and GitHub's Codespaces extension and Microsoft's Remote-SSH extension are not published there. Antigravity Codespaces Pro is published on Open VSX and connects over plain SSH through the GitHub CLI instead.

Which Remote-SSH extension should I use?

Cursor: anysphere.remote-ssh (bundled). VS Code: ms-vscode-remote.remote-ssh. VSCodium and Kiro: jeanp413.open-remote-ssh. Windsurf: its built-in SSH only; do not install another Remote-SSH extension.

Why does my codespace disconnect during long AI agent runs?

Either the network drops an idle SSH connection, or GitHub stops the codespace after its idle timeout. The extension writes SSH keepalive settings (ServerAliveInterval 30, ServerAliveCountMax 10) for the first; the second is a setting in your GitHub Codespaces preferences.

Which version is on the VS Code Marketplace?

The Marketplace currently has an older version (4.3.0). The latest, 5.3.2, is on Open VSX and as a .vsix in the GitHub release.

Is it free?

The extension is free and open source under MIT. "Pro" is part of the name, not a paid plan. Codespaces usage itself is billed by GitHub to your account or organization.

Where do the usage numbers come from?

Only from GitHub's billing API for the active gh account, which needs the user scope. If the API fails, the extension shows "Usage unavailable" with the reason. It never estimates.
