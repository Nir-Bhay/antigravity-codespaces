Codespaces quotas explained: core-hours and GB-month

By Nirbhay Hiwse · 21 October 2026 · 7 min read

Most surprises on a Codespaces bill come from two misunderstandings: that hours are wall-clock hours, and that stopped codespaces are free. Neither is true.

Two separate quotas

Each month GitHub includes a compute quota and a storage quota for personal accounts. They are tracked separately and one cannot be used to pay for the other.

PlanComputeStorage
GitHub Free120 core-hours15 GB-month
GitHub Pro180 core-hours20 GB-month

Organization-owned codespaces do not use these quotas; they are billed to the organization. Source: About billing for GitHub Codespaces.

Core-hours, not hours

A core-hour is one CPU core running for one hour. The machine size multiplies everything:

MachineCore-hours per hourHours from 120 core-hoursHours from 180 core-hours
2-core26090
4-core43045
8-core81522.5
16-core167.511.25
32-core323.755.6

So on GitHub Free, a 4-core codespace gives you 30 hours a month, not 120.

Storage keeps counting when you stop

Storage is charged for as long as a codespace exists, running or stopped. A GB-month is one gigabyte kept for a whole month. A 10 GB codespace kept for half a month uses about 5 GB-month. Deleting codespaces you no longer need is the only way to stop the meter.

Seeing the real numbers

The Cloud Hub reads these figures from GitHub's billing API for the active account, which needs the user scope. It shows compute and storage on separate bars and never estimates when the API cannot be read. See Usage analytics.
