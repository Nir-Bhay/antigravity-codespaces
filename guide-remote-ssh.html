Remote-SSH in VS Code forks, compared

By Nirbhay Hiwse · 21 October 2026 · 6 min read

Short answer: Microsoft's Remote - SSH is licensed for use with Microsoft Visual Studio Code and is not on Open VSX. Cursor bundles anysphere.remote-ssh, Windsurf has built-in SSH, and VSCodium and Kiro use the MIT-licensed jeanp413.open-remote-ssh.

Why can forks not use Microsoft's extension?

The Remote - SSH licence allows use of the software “with each validly licensed copy of Microsoft Visual Studio Code”. The VS Code Remote Development FAQ adds that the Remote Development extensions are not open source. The extension is also not on Open VSX: the API returns not found for ms-vscode-remote/remote-ssh (checked on 21 October 2026).

What is the open alternative?

jeanp413.open-remote-ssh is published on Open VSX under the MIT licence (source). Its README notes that on some editors it depends on a proposed API that must be enabled in argv.json.

What does Antigravity Codespaces Pro need from them?

Only the ability to open vscode-remote://ssh-remote+<host> for a host defined in ~/.ssh/config. Setup Doctor recognises jeanp413.open-remote-ssh, ms-vscode-remote.remote-ssh, vsx-remote-ssh.vsx-remote-ssh, anysphere.remote-ssh, and any extension whose ID contains remote-ssh (systemDoctor.js).

Which one should I use?

The one your editor ships or recommends. Installing two Remote-SSH extensions in the same editor can conflict, which Windsurf documents explicitly.
